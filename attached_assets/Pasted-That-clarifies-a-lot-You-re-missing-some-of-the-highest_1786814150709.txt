You’re missing some of the highest-signal tactical ingredients:
•  Press intensity (PPDA / high-press vs mid-block vs low-block)
•  Zonal involvement (where on the pitch the player actually operates and produces actions)
•  Performance variation by opponent style and game state
Without those, pure statistical projections stay relatively blind to context, which is exactly why you’re trying to build a tactical memory layer.
Here’s how to think about solving this realistically:
1. You don’t need perfect data to start improving
You can create useful proxies and structured knowledge even with incomplete sources:
Press intensity proxies
•  Opponent’s average possession
•  Opponent’s passes allowed per defensive action (if available anywhere)
•  Style labels you assign yourself (“High press”, “Mid block”, “Low block”, “Man-oriented”, etc.)
•  How the player’s volume changes against teams you have already tagged that way
Zonal / role proxies
•  Position + role tags you already use (Ball-Playing CB, Progressive Fullback, etc.)
•  Progressive actions, carries, passes into final third, touches in attacking third (if your current data has any of these)
•  Average starting position or heatmap summaries if you can get them from anywhere
Opponent & scenario variation
•  Tag opponents by style rather than just strength
•  Track how the player’s key metrics move in high vs low possession games
•  Track performance when the team is leading / trailing / drawing (game state)
Even imperfect tags become powerful once you store them as memory and retrieve them consistently.
2. Best practical path right now
Short-term (what you can do without new data sources)
•  Manually or semi-automatically create style profiles for the main teams in the leagues you cover.
•  Create role archetypes with expected behavior under different conditions.
•  Start logging, for every game you care about, a few extra fields: opponent style tag, expected possession split, game script, and the player’s actual output.
•  Feed those into your memory system.
This already lets the app say things like:
“Klarer usually sits in the 68–75 pass range, but against high-pressing sides away from home his volume has historically compressed toward the low 60s.”
Medium-term
•  Look for secondary data sources that do have PPDA, zonal touches, or pressure data (even if delayed or limited).
•  Or scrape/publicly available advanced stats sites and normalize them into your own schema.
•  Start building a lightweight knowledge graph or well-tagged database of “Player X vs Style Y → typical effect on Metric Z”.
Longer-term
•  Either partner with / buy better event data, or accept that some of the deepest tactical intelligence will still come from a strong LLM that has been grounded with the best proxies and historical patterns you do have.
3. How this feeds the “memory” idea
The memory doesn’t have to contain perfect press intensity numbers. It needs to contain reliable relationships and conditional expectations.
Example memory entries that are already useful:
•  “Ball-playing CBs in Championship when expected possession ≤ 47% and opponent is tagged High Press → average pass attempts drop ~9–12% from base.”
•  “Klarer progressive pass rate stays relatively stable even when total volume falls.”
•  “In low-scoring scripts, volume from deep players is more resilient than from advanced midfielders.”
You build these relationships over time from the data you can get, then retrieve them when generating the write-up.
