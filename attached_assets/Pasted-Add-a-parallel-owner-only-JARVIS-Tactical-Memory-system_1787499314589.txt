Add a parallel owner-only JARVIS Tactical Memory system without changing any subscriber-facing Reverse Picks flow, prediction engine, UI, or existing endpoint behavior. The goal is to give JARVIS persistent long-term football intelligence that can be retrieved automatically before every Script Hunt and player audit. Create structured storage for four memory classes: team tactical fingerprints, player exact-role memory, matchup interaction memory, and settled-pick postmortem lessons. Every record must include entity IDs, team/player/opponent, league, manager/regime ID, formation, venue, prop type where relevant, date range, sample size, source/provenance, confidence, created_at, updated_at, valid_from, valid_to or stale_after, and a structured payload. Team fingerprint payloads should support buildup style, directness, central-vs-wide progression, hub concentration, goalkeeper involvement, CB recycling, pivot usage, press intensity/type/triggers, defensive block height, compactness, transition tendency, counterattack preference, possession preference, score-state behavior, home/away differences, and press response. Player-role memory should store exact role, buildup share, progression route, leading/trailing behavior, substitution/minutes patterns, teammate-volume dependencies, and role confidence. Matchup memory should store how one team’s press/block affects specific opposing roles, including whether CB/GK circulation is allowed, pivots are screened, wide traps are used, midfield is bypassed, or long distribution is forced. Postmortem memory should store predicted script, actual first scorer, actual possession, actual pressing/block behavior, actual buildup routing, player minutes/stat result, HIT/MISS, whether the pick hit for the expected reason, failure mechanism if not, and reusable lesson tags. Add authenticated owner-only operations such as getTacticalMemory, getTeamFingerprint, getPlayerRoleMemory, getPostmortemMemory, upsertTacticalMemory, and savePostmortemMemory, with bounded filtered responses and no provider secrets. Current verified fixture/lineup/news evidence must always supersede stale memory; memory is advisory evidence only and must never alter immutable Bayesian production math. Add regime invalidation rules so manager, formation, transfer, key injury/return, or tactical-role changes mark older records stale rather than deleting them. Ensure JARVIS can retrieve relevant memory by team, opponent, player, role, manager/regime, venue, prop type, and date range before every audit. Preserve provenance and version history so changes are auditable. Do not expose owner-only tactical memory to normal subscribers unless explicitly requested later.
